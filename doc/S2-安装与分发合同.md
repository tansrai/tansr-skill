## 命令与状态

拟定入口：`npx --yes @tansr/skill@latest install --host codex --scope project --yes`。用户可在希望开发产品的目录将指令交给助手执行，也可使用有确认步骤的交互入口。前一个`--yes`处理npm下载确认，最后一个确认本工具已明确指定的宿主/范围写入。

支持 `install`、`preview`、`status`、`update`、`rollback`、`uninstall`、`recover`，以及 `hosts`、`--help`、`--version`。`--host` 精确指定一个宿主，`--scope project|user` 明确范围；`--project` 用于项目绝对路径，默认当前目录。`--json` 输出结构化结果且不等待输入；更改需 `--yes` 或本次交互确认。无交互且缺目标/确认时返回明确错误和下一步，不自行写入所有宿主。

安装结果分别表示：文件已安装、静态结构有效、助手发现待验、实际调用待验。文件存在或 CLI 正常退出不证明助手已加载；安装完成给自然语言产品需求示例与宿主重载指引。

## 0.1.1多助手扩展合同

依据用户2026-10-08追加要求及“优先编程／Agent产品”的选择，`installer/hosts.mjs`作为唯一执行注册表；CLI参数校验、别名、交互列表和scope菜单均读取它，不再维护另一份固定白名单。`hosts --json`给出真实范围、原生目录、官方来源和加载提示；一次操作仍只选一个目标，不自动探测后写入所有助手。

通用`.agents/skills`是多个已知宿主采用的约定，不是所有助手强制遵循的全局注册表。Codex与generic指向同一位置；用户选择它时应理解会被支持该目录的其他宿主看到。各地区IDE/CLI差异分别建profile，ZCode在官方证据仅充分支持用户目录时只开放user。名单和完整路径见[助手安装说明](../references/assistant-setup.md)，不在此重复维护。

Kimi Code新实现的`.kimi-code`不与已归档kimi-cli的`.kimi`混用。已核实的用户根环境覆盖按官方语义解析，并要求绝对路径；MiniMax根覆盖取去空白后的MINIMAX_DATA_DIR，再取MAVIS_DATA_DIR。无法核实的自定义配置根或命名profile明确报错，不悄悄写入未被宿主使用的默认目录。

Kimi项目目标需为最近Git根，子目录操作提示根路径且不自动改写父目录，支持`.git`文件及目录标记。MiniMax内部profile只要非空（包括default与空白）就要求显式数据根。generic/Codex管理同一物理目录，更新、回退、卸载影响所有消费者，metadata.host不是独立所有权空间。

飞书aily为云端导入；元宝、豆包、火山及TRAE国际版中尚未核实本地路径的产品保留具名指引。它们不会被显示为可自动安装的目录适配，调用时在加载文件引擎和写入之前返回`host_manual_setup_required`及官方入口。后续拿到明确合同和实际验收后再开放相应范围，不借同集团其他产品的目录代签。

原安装事务、用户文件保护、路径检查、更新/回退/卸载语义保持。别名仅归一为canonical host ID；既有0.1.0/0.1.1安装记录经受管迁移继续管理，不接管未知目录。多助手0.1.1已候选发行；因宿主发现事务备份，修复候选为0.1.2，Web/Node模板和SDK/Serve发行基线不变；真实发布事实另记回执。

## 文件归属与恢复

- 安装管理确定目标 `skills/tansr`、扫描树外的 `dirname(skills)/.tansr-installer-state-<目标路径SHA256前16位>`，以及旧 `skills/.tansr-installer-state` 的无payload版本防回写标记。首次目标已存在却无可信安装记录时拒绝接管；不提供盲目强制覆盖。
- 清单验证路径、重复/大小写冲突、Windows保留名、字节和哈希；拒绝符号链接、junction、硬链及路径逃逸。操作前后核验目标父链。
- 完整校验随包内容并暂存后，逐受管文件提交，写前journal提供回退/恢复，状态终态原子提交；不承诺整个目录瞬时切换或断电耐久。状态只记录版本、清单及公开宿主/范围，不写凭据或遥测。更新保留前版恢复入口；未终态时必须报告incomplete，不能假报成功。
- 并发由进程锁拒绝；不按时间超时盗锁。异常写入可诊断事务记录，显式 `recover` 才处理已退出进程留下的事务。
- 用户修改和未知文件保留；更新、回退、卸载按登记归属核对，冲突不伪报完整成功；不递归清空整个宿主技能目录。
- 所有破坏性文件处理必须限于经过校验的本工具自有目标，不跟随链接；失败不改变用户项目的其他内容。
- 0.1.2 的暂存、备份与事务记录全部在扫描树外。迁移先持有兼容旧版的锁，校验登记内容，再发布迁移标记并逐项移动；历史字节保留，迁移未终态只允许显式恢复。旧位置永久保留无技能内容的标记，旧版不能重新创建有问题的布局。只读 `status` / `preview` 不迁移。内容回退不退回旧状态布局；后续使用修复版安装器管理。

安装记录 schemaVersion=1，字段为 name、version、managedFiles（逻辑路径/大小/SHA256/文件模式）、metadata、complete、installedAt、lastTransactionId。metadata 仅接受 packageName、packageVersion、skillVersion、host、scope，以及 templateBaselines/runtimeBaselines 的已知公共字段；不接受任意扩展数据。记录在扫描树外专属状态目录，事务日志和恢复材料与该记录、完整目标目录身份绑定。回执固定包含 action、ok、exitCode、status、targetPath、statePath、legacyStatePath、stateLayout、migrationRequired、version、changes（added/updated/removed）、preserved、warnings、recoveryRequired；readiness 中文件/静态结构与宿主发现/实际调用分列。待迁移时 `statePath` 指向计划的新目录，`legacyStatePath` 指向当前旧状态，警告说明所需操作。
