## 1. 为什么做这次首页调整

### 1.1 公司初心与产品方向

云联慧算的理念是“联通世界、服务全球”。Tansr 是公司主要对外产品方向，承担智能体与人类之间的中立桥梁角色：为智能厂商连接算力与真实需求，为开发者提供快速发展路径，为终端用户降低智能接入门槛，为智能体提供不同形态的落地通道。

用户对总体构思的原话包括：

> “我们要做的是一个技术包装产品。”
>
> “让任何用户只需要2步就可以拥有自己的任何形态的产品。”
>
> “我们中立，我们不予任何智能厂商竞争，我们只做桥梁。”
>
> “将每个层次的用户的认知成本降到最低。”

这里的技术包装落实为技术产品化：把复杂的通用智能体能力组织成可复用 SDK、开发引导和运行服务，使用户更容易获得自己的 AI 产品。SDK 与 Harness 是实现这一价值的基础；首页需要先让用户理解所得，再按需要说明实现方式。

“任何用户”包括当前没有开发经验的人。当前让这些人通过已有智能助手与 Tansr Skill 开始构建，不将他们推迟到未来自有助手阶段才覆盖。“任何形态”是持续拓展生态的目标；页面具体支持清单按真实发行和验收范围展示。

### 1.2 四种不同层级的规划必须分开

| 层级 | 已明确的内容 | 首页如何使用 |
| --- | --- | --- |
| 长期发展路线，四步 | 强化 CLI / SDK / Serve 与 Harness，使智能体具备行动力；扩展全平台生态并推进核心开源；建设综合生态平台，最终由智能体自主治理运营；与智能体及人类共同发展 | 放在品牌、生态或发展方向说明中，未来事项明确为规划 |
| 近期推广路径，两阶段 | 先借助已有助手建立生态与知名度；品牌、能力成熟且具备自有助手后，提供更直接的创造入口 | 决定当前主入口，不把未来助手伪装成已上线能力 |
| 当前用户体验，两步 | 安装 Tansr Skill → 向同一个智能助手描述需求 | 首页可见、可操作、可验证的主要路径 |
| 本轮工程实施，三阶段 | Skill 集 → npx 安装与发布 → 新引导首页 | 用于工程执行，不展示成用户必须完成的三步 |

未来的“描述想要的产品 → 选择它运行的平台”单独作为发展方向。当前产品构建过程中的必要澄清、环境准备、应用配置及发布选择仍由助手逐步引导；两步入口不意味着两次点击完成任意产品并自动上线。

### 1.3 本轮讨论形成的设计决定

| 来源 | 本轮保留的含义 | 对设计的约束 |
| --- | --- | --- |
| 用户要求“大标题简明阐述 Tansr 的意义” | 首屏直接说清用户可以得到自己的 AI 产品 | 不能让用户先理解 SDK、Harness 或模型协议才能知道产品价值 |
| 用户定义四层：普通人、入门开发者、成熟技术与产品人员、组织与企业 | 同一产品面向四种需求深度，各有痛点和引导口号 | 内部保留完整画像，对外按需求表达；不以学历、职级做身份门槛 |
| 用户要求第一、二层讲清“智能产品”和“少做重复 Harness 开发” | 第一层明确 AI 产品，第二层明确智能体通用能力复用 | 不泛化为“实现梦想”“效率工具”，也不缩成普通模型 API 接入 |
| 用户确认“分层就基本构成了” | 四层作为本轮内容基准 | 视觉调整不能删层、合并掉关键价值或变成四档收费套餐 |
| 用户要求先落详细方案，防止语义漂移或灭失 | 记录背景、语义、设计理由、实施与验收映射 | 初次登记仅文档；用户随后授权实施。每次改变关键内容时回查本文件，并在实施回执记录实际结果 |

## 2. 内容语义基准

以下编号是语义引用标识，不是新增工程卡。

| 标识 | 必须保留的语义 | 开发中常见的错误变化 |
| --- | --- | --- |
| M01 | 面向每个人，包含无开发经验者，当前就能通过助手与 Skill 起步 | 首屏重新只对专业开发者说话；普通人仅在愿景里出现 |
| M02 | 用户得到的是自己的 AI 产品，有适合目标形态的交互或调用入口、业务流程和可使用的结果；包括图形应用、CLI、Node及服务等形态 | 只展示一段回答、聊天框、代码片段或规划文档就称产品完成，或把所有产品误限定为GUI |
| M03 | 通过通用智能体能力复用减少重复开发 | 只剩模型聚合或 API 转发；宣传开发者无需再做任何业务工作 |
| M04 | 当前路径是安装 Skill，再向同一个助手描述需求 | 首页直接出现会让人误认为自有构建助手已上线的聊天输入框 |
| M05 | Skill 帮助开发；SDK / Harness / Serve 支撑应用运行 | 把 Skill 本身描述成运行时 SDK；把安装 Skill 描述成已经部署产品 |
| M06 | 新建产品、为已有产品接入 AI 两条路径都存在 | 所有人都被引导创建新工程，或者必须更换技术栈 |
| M07 | 开发者保留业务、架构、数据授权、界面与经营方式的决定权 | 宣称 Tansr 自动代替应用登录、业务授权或上线验收 |
| M08 | 中立桥梁连接厂商、开发者、终端用户和智能体 | 只宣传某一家厂商，或宣称当前已经适配一切模型、平台与行业 |
| M09 | 组织层关注接入、管理、持续运行和业务发展 | 用虚构客户、规模、节省金额、收益或工业场景能力作证明 |
| M10 | 两步是降低起步成本的体验目标 | 宣称零准备、无账号、免费无限调用、固定几分钟或自动发布 |
| M11 | Skill 的 MIT 许可与核心开源计划分别表达，保留用户此前去除主页开源日期的要求 | 因Skill已开源就宣布全部内核已MIT开源，恢复已移除的首屏日期，或把正文仍有日期误记为整页已完成去日期 |
| M12 | 四层是四种价值入口，可自由跳转 | 四档产品、四档套餐、强制身份问卷、必须逐层解锁的流程 |

这些含义适用于中文、英文、页面正文、SEO、按钮说明、复制给助手的文本、后台预览及相关帮助内容。美化与压缩不能只保留口号而删去支撑含义。

## 3. 四层画像、口号与出口

痛点是当前设计假设，不包装为已完成的用户研究。身份描述供内部使用，对外使用需求语言。

| 层 | 内部画像与核心问题 | 中文口号 | 简短说明 | 引导出口与依据 |
| --- | --- | --- | --- | --- |
| L1 | 普通用户，无开发经验；“我知道需要什么，但不会把它做出来” | **把你的想法，做成自己的 AI 产品。** | **向智能助手描述需求，让 Tansr 帮你开始构建。** | “开始做我的产品”进入两步引导；用真实演示界面展示输入、动作和结果 |
| L2 | 有编码基础的入门开发者；“能写功能，却被智能体运行与接线卡住” | **少做智能体底层开发，更快做出 AI 产品。** | **复用 Tansr Harness，减少模型调用、工具执行、会话与权限等通用能力的重复开发。** | “查看开发起点”进入示例与起步引导；保留 SDK 和文档直达 |
| L3 | 高级工程师、产品经理、技术或产品负责人；“要交付，也要保留架构与产品控制权” | **按你的业务和架构，把 AI 做进产品。** | 沿用自己的业务、数据和产品体验，接入可复用的智能体能力。 | “查看集成方式”进入 `/sdk`；已有项目示例与边界说明支撑 |
| L4 | 组织、公司、成熟产品运营者、工业业务团队、企业领导与创始团队；“要进入业务，也要长期可管理、可发展” | **让 AI 成为业务能力，随企业一起成长。** | 连接业务应用，管理权限与用量，为持续运行和扩展提供支撑。 | “了解企业接入”进入 `/cooperation`；组织、应用、权限与用量能力支撑 |

L1/L2 的口号和说明按本次明确确认文字保存。L3/L4 口号沿已认可的四层讨论基线，补充说明与按钮为设计建议。后续修订要区分“措辞优化”和“价值定位变化”。

### 3.1 第一层的呈现规则

- 首屏主要面向 L1。先出现产品所得，再出现操作方法；不以代码大图作唯一成果证明。
- 选一个看得懂的真实演示产品：例如录入活动、查看历史和建议的健身助手。说明是演示，不能暗示诊断或治疗能力。
- 给出“输入 → 操作 → 可见结果”的具体小流程，不以“模型已经完成”的文本代替实际页面结果。
- 没有编程助手的用户可以打开简短帮助，知道需要先选择和安装一个助手；不得假设所有普通用户都认识 Codex、WorkBuddy、Node 或终端。

### 3.2 第二层的呈现规则

- 首次出现 Harness 时紧邻中文解释：“智能体运行所需的通用基础能力”。口号不要求用户先懂这个词。
- 用一组简短分工表达价值：开发者组织业务、数据和界面；Tansr 提供通用智能体运行能力。
- 初次展开只展示必要能力，例如模型调用、工具执行、会话和权限；更深技术说明由 SDK 页面与文档承接。
- 示例必须消费正式 SDK 的真实接口。保留 SDK npm 安装入口，不能把它和 Skill npx 安装混为一个命令。

### 3.3 第三、四层的呈现规则

- L3 同时承接成熟团队创建新产品和已有产品接入，不能用“已有产品”作为唯一资格条件。
- L3 展示业务工具、会话、权限、事件与用量的分工；不承诺不经集成即可继承业务授权。
- L4 将成本可观察、组织与应用管理、持续运行等作为证据主题。实际支持范围从产品与合同核实，不能由营销文案推导新能力。
- 工业是用户场景来源之一，首批可说明已能支撑的资料、工单、检查报告等方向；具体案例仍要有实现依据，不能仅因写入画像就宣布已具备完整工业解决方案。

## 4. 信息架构与页面布局建议

### 4.1 一条主线、四个可直达入口

理解主线为“我能得到什么 → 怎样更快做出来 → 如何接入并掌控产品 → 如何支持业务持续发展”。四层是信息深度，不强制变成四个全屏，也不要求按次序阅读。

首版建议用可直接链接的分区和需求导航。关键文案全部在服务端输出，不藏在必须点击、自动轮播或等待动画才能出现的内容里。不引入必须先选择“我是新手/专家”的身份分类。

需求导航建议文案：**我有一个想法 / 我想更快开发 / 我要自主集成 / 我要业务接入**。这些是页面跳转入口，不改变账号角色、套餐、权限或安装范围。

### 4.2 首屏结构

1. 保留原导航、品牌、语言和主题切换。
2. 唯一 H1 建议直接使用 L1 已确认口号：“把你的想法，做成自己的 AI 产品。”，避免再叠加一条近义大标题。
3. H1 下使用 L1 简短说明，并用两步短句说明当前方法；没有操作上下文时不把“描述需求”暗示为本站直接生成。
4. 主操作为“开始做我的产品”，链接到同页两步引导 `#start`；引导区域应可独立链接，不能只依赖弹窗。
5. 次操作为“查看产品示例”。SDK 文档、原快速集成登录入口、SDK 安装与 Demo 下载作为可发现的专业入口保留，视觉上不与主操作并列争抢注意力。
6. 保留SDK定位胶囊与“MIT开源计划”相邻、前者在前、首屏胶囊不显示日期的既有规则；信息层级低于价值标题与主操作。当前正文组件仍显示配置日期，整页去日期应作为待统一事项记录，不能写成已有完成事实。
7. 展示一个真实成果预览；动效用于解释输入与结果，不伪装成正在调用模型。
8. 提供四个简短需求导航；移动端可自然换行，不强制横向滚动。

布局尺寸以内容和视口决定，避免沿用强制换行造成超大字体挤压。首屏不新增一套背景或主题系统。Desktop 与移动端在 S3-03 实际预览后确定字号、间距和图文比例。

### 4.3 与原“第二屏价牌”要求协调

当前首页代码顺序为 `Hero → SdkPricing → OpenSourcePromise → BusinessLinks → 其他介绍`，用户此前明确要求首页第二屏展示 SDK 套餐。当前源码保证的是第二个主要区块，不是固定一个视口高度后的像素位置；Hero 内容增长会下推价格。**本次四层设计未明确撤销这个位置要求。**

默认方案保留价牌为 Hero 之后的第一个主要区块。首屏已承担 L1，并提供通往后续引导与各层的跳转；价牌后再展开两步说明、L2/L3/L4 的价值与证据。四层不依赖连续四屏才能理解。

价牌区域保留“仅针对 SDK 使用”的清楚说明，免费卡与权益按实际配置读取，不把 MIT 许可等同于模型调用免费，也不让普通用户误以为阅读示例、查看安装指引必须先买套餐。不得复制一套静态价格到四层内容中。

若后续视觉评审希望将套餐移到四层说明之后，可展示该布局提案及理由，待用户明确选择后修改原位置合同。此项是布局决策入口，不阻塞本轮方案完成，也不作为新工程卡。

### 4.4 页面区块与内容去向

| 建议顺序 | 内容职责 | 行为 |
| --- | --- | --- |
| 首屏 | L1 价值、两步摘要、成果预览、四种需求入口 | 主入口到 `#start`，示例到 `#examples` |
| 原第二主要区块 | SDK 套餐 | 继续消费原目录、免费卡、大规模/超大规模切换和原交易入口 |
| 两步引导 `#start` | 安装 Skill、描述产品；未安装助手与环境不足的帮助 | 复制给助手为主，命令模式为辅 |
| 开发起点 `#build` | L2：少做重复 Harness 开发 | 正式示例、SDK 与文档入口 |
| 自主集成 `#integrate` | L3：保留业务和架构控制 | `/sdk` 及已有项目示例 |
| 业务接入 `#business` | L4：组织、管理和持续发展 | `/cooperation`，SDK 套餐入口仍复用原页面 |
| 产品示例 `#examples` | 健身和另一个领域成果；新建与已有项目两种起点 | 真实截图/录像、Demo 下载、需求示例 |
| 技术与生态证据 | 按层归并现有能力说明、CLI/SDK/Serve、工具、扩展和治理内容 | 保留专业资料与原导航目的地，减少近义重复内容 |
| 开放方向、FAQ、页脚 | 回答起步、费用、控制权、支持范围、开源状态；保留支持及备案 | 沿用原链接与后台配置 |

已有区块不因“精简”而直接删除。S3-01 为每个旧区块登记“保留 / 合并到哪层 / 移到哪个既有页面 / 待决定”，所有旧导航锚点须有有效去向或兼容锚点。

## 5. 两步引导的交互合同

### 5.1 开始构建

匿名访问即可阅读价值、示例、安装说明和复制内容，不将注册登录作为查看安装指引的前置。需要平台应用配置或实际调用时，再清楚引导到现有账号与控制台。

`#start` 保留两个明确步骤：

- 第一步“让你的助手装好 Tansr Skill”：选择当前使用的助手，复制安装指引交给它。没有助手时展开帮助；用户熟悉命令时可切换至“查看安装命令”。
- 第二步“告诉它你想做什么”：展示可编辑的需求示例，并说明回到同一个助手继续。可以描述新产品，也可以要求为当前项目加入 AI。

宿主未选时不静默默认成另一款助手；先提供选择提示。项目/用户范围用“仅当前项目 / 在我的项目中通用”等可理解措辞解释，实际仍严格对应 `project` / `user`。不默认为用户写所有检测到的目录。

### 5.2 命令与助手交接

截至本地已验记录，Skill 正式基线为 `@tansr/skill@0.1.3`，`latest` 已提升至同版本。以下为已发布合同示例，不是让网站在浏览器执行的代码：

```sh
npx --yes @tansr/skill@latest install --host codex --scope project --yes
```

WorkBuddy 的 host 为 `workbuddy`。实际助手指引宜先确认工作区与环境、预演目标，再安装并核对真实加载；未知工作区、旧安装冲突、未保存改动需要明确处理，不能为了“两步”覆盖文件或省略安装边界。

命令来源为 Skill 仓 `release.json`、`installer/hosts.mjs` 的合同，以及发布后 README / S2 回执确认的发行状态。`INSTALL.md` 与包内 `compatibility.json` 可能保留构建时的 candidate / not_tested 快照，不能用它们单独否定发布后事实，也不能据目录安装支持推断全部助手已真实加载通过。

S3-04 形成一个供主站消费的受控安装信息模块：记录包名、已验版本、命令模板、host/scope 允许组合、来源提交与核对日期。现有工具若已有可用导出则复用；新增快照须可再生成或校验，禁止手工维护多份宿主映射。浏览器运行时不读取私有仓、不抓取 npm 状态、不执行安装程序。

主入口沿用已验 `@latest` 命令；帮助区提供精确已验版本。上线前再次核对公开 latest 与候选消费结果，不把两种版本语义混写。未来 latest 漂移后的同步、验证和回退属于发行维护，不以首页静态版本永久代表 registry 最新状态。

复制给助手的文字应包含：当前目标、所选助手与范围、必要环境检查、预演及安装方式、冲突保留、实际读取入口的确认、安装完成后继续需求构建。不得包含本机专属路径、明文凭据、账户充值授权、付费调用授权或自动发布授权。

## 6. 证据、文案和视觉的分工

- 每层统一采用“口号 → 一句解释 → 一个具体证据 → 一个主要出口”的结构，避免同一层同时出现多组同等权重口号。

- 产品示例只使用 E1 已核验资产，保留来源、界面版本、离线/真实调用属性及当前可访问方式。截图不是在线演示；演示产品不是客户实绩；平台构建成功不是全部渠道已发行。
