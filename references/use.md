# 帮用户使用 Tansr

先识别用户卡在助手准备、登录、选模型、运行、应用接入还是计费。给一个能执行的下一步，并说明完成后应该看到什么；不要求用户先读架构说明。只回答产品问题时不创建工程或更改账户。

## 先找到用户当前的入口

| 用户想做什么 | 下一步 |
| --- | --- |
| 让自己的 Codex / WorkBuddy 使用 Tansr Skill | 打开[助手准备](assistant-setup.md)，使用正式 `@tansr/skill` 安装入口，按实际宿主核对目录与加载。安装文件不等于助手已读取。 |
| 描述需求，让助手做一个产品 | 一句普通需求即可，按[需求与产品说明](product-brief.md)补齐必要信息、说明默认项并按[应用开发](build.md)实施；不依赖首页追加配置指令。没有平台账号时也完成所需本地后端、界面、业务流程和明确标记的离线验证。 |
| 让已经写好的应用调用 Tansr | 按下文完成账号、应用和服务端配置，再按项目实际使用的 [SDK](sdk.md) 或 [Serve](serve-mobile.md) 接线。 |
| 自己在终端使用 Tansr | 进入下文 CLI 步骤。CLI 不是安装 Skill 或开发所有应用的前置条件。 |

2026-10-07 已核实 npm 正式包：`@tansr/sdk@0.18.1`、`@tansr/serve@0.15.0`、`@tansr/cli@0.10.2`，要求 Node ≥ 22.19。实际发行、模板与各平台验收范围分别见 [compatibility.json](../compatibility.json)；构建时的状态不是用户新工程已经运行的证明。已有项目沿用锁文件，只有确认需要并验证影响后才升级。

## 把自己的应用接到平台

先从对话和本项目的安全配置状态判断；仍不清楚时主动用普通语言问“你已经在 Tansr 创建过应用了吗？”已有应用直接复用，没有则给下列获取路径。不要要求新手先知道 `.env`、换票或 SDK 的含义，也不因缺少应用而停掉界面和业务开发。不要求用户再购买供应商密钥；账号、创建应用及费用操作使用实际控制台，没有自动注册或充值承诺。

1. **找到或创建应用。** 打开[应用管理](https://www.tansr.com/console/apps)，未登录先完成登录/注册。已有应用选择目标条目；没有可打开[创建应用](https://www.tansr.com/console/apps?create=1)，确认个人/组织归属、平台类型与用途。助手可协助已授权操作，密码/验证码由用户在平台输入。创建成功的密钥弹窗显示 `ApiKeyId`（即 App ID）和 App Key；长期密钥仅在创建或轮换时显示一次，应直接保存在本机受控配置中。
2. **确认应用能用什么。** 在该应用的实际配置中核对模型授权、所需文字/媒体能力和当前额度。按钮名称和可选模型以界面为准；系统角色、模型授权和工具权限分别配置，修改提示词不会自动开通能力。
3. **定位已有 App ID / Key。** 应用详情为 `/console/apps/<URL编码后的App ID>`，详情显示 `ApiKeyId`（即 App ID）与密钥前缀，不提供已创建完整 Key 的反查。用户已保存的 Key 直接复用；丢失时才解释轮换入口及影响：旧 Key 会立即失效，相关后端必须同步更新。不要为找回密钥擅自轮换，不把 ApiKeyId、前缀、CLI PAT 或供应商 Key 填作 App Key。
4. **由助手协助安全配置。** 告诉用户：“`.env` 是这个产品后端的本地设置文件，用来保存连接信息，不是要发给我的附件；是否支持离线/平台切换取决于这个工程。”按下节完成文件准备、安全录入、模式切换及本项目检查。若缺少后端、配置读取或换票端点，助手按[前后端交付](build.md#把所需后端一起交付)一起补齐并启动；只填变量不等于接通平台。App Key 不进入浏览器、手机、Electron 安装包/renderer、公开仓库或日志。
5. **沿现有登录确定用户身份。** 后端从经过验证的登录态得到用户 ID，复用 Serve 的平台工厂或已发行的 `createAppTokenMinter` 换取短期票，具体见 [SDK 接入](sdk.md)。普通网页/移动端连接自己的后端；短期票的使用位置按所选形态处理。不能让客户端自报用户 ID 来决定数据或会话归属，也不能用 CLI PAT 替代应用密钥。
6. **先检查本地，再做一次真实验证。** 按实际项目 README 和 `package.json` 运行配置检查、已有测试及启动命令；不要猜测所有项目都有同一个脚本。无凭据时明确显示离线模式，继续可完成的本地工作。有真实调用授权后，用一条已确定的小任务验证模型输出和业务动作，并回查请求结果与用量。已有明确授权不反复询问；未授权的付费调用才说明费用范围。换票成功、HTTP 202 或页面显示“完成”都不单独证明业务成功。

产品形态与应用管理中的平台字段分开理解：电脑程序对应 `desktop`；Android、iOS、原生鸿蒙对应 `mobile`；网站后端或服务对应 `server`。`web` 可以表示产品目标，但不是应用创建 API 的有效 platform 值。沿当前界面选择，不把首页需求标签原样传入 API。

## 本机配置与凭据处理

本节适用于用户要求接入平台时，不是每个普通开发任务的审批流程。保留已有项目的环境变量管理和秘密存储，不强制改用模板 `.env`。

- **助手准备。** 确认工程绝对路径、实际服务端配置读取方式和忽略规则。没有 `.env` 才从本工程 `.env.example` 创建；缺少配置样例时先依据实际后端读取字段建立不含秘密的样例，不覆盖已有文件。不读取/打印整份真实 `.env`，不复制凭据到命令参数或终端历史。向用户给出指向实际后端配置文件的可点击绝对路径，宿主支持时直接打开该文件；沿用秘密存储的项目则给已有安全配置入口。链接只含位置，不含值，让用户按实际读取字段录入：Web 起步工程使用 `TANSR_APP_ID` / `TANSR_APP_KEY`，本 Skill 支持的官方 token-server / Serve 工程使用 `TANSR_APP_KEY_ID` / `TANSR_APP_KEY`。`TANSR_APP_ID` 与 `TANSR_APP_KEY_ID` 都填目标应用创建弹窗或详情展示的 `ApiKeyId`（App ID），只是模板字段名不同；不从秘密值前缀推断标识，也不能把标识填作 `TANSR_APP_KEY`。日常诊断只报告模式、变量名和缺失/空/占位/注释/重复等状态。
- **协助启用。** 提醒行首 `#` 表示注释，填写到注释后不会生效；每个变量仅保留一个确定赋值。对当前 helper 可识别的 Web 起步工程及官方 token-server / Serve 工程，从 Skill 根执行 `node scripts/configure-project.mjs --project <工程绝对路径> --mode platform` 预演；用户已明确接平台且安全值已填妥时，加 `--apply` 激活 `.env` 内唯一明确的配置。Web 按 `TANSR_MODE` 切换；token-server / Serve 固定使用 platform，不写 `TANSR_MODE`，也不支持 `--mode offline`。这些后端已有有效 `TANSR_MODE` 时先按诊断消除无效设置。helper 仅更新既有 `.env` 中已确认的赋值，保留其他内容和权限；不创建文件、不改登录配置、不接收密钥参数、不联网、不收费、不启动服务；遇到缺失或歧义先按输出解决。未识别的既有后端沿本项目实际配置入口处理；早期安装包先核对实际支持，不能虚报执行。
- **校验与重启。** 对当前 helper 可识别的 Web、token-server / Serve 工程运行 `node scripts/doctor.mjs --project <工程绝对路径> --mode platform`，其他工程使用自身实际检查入口；本机检查不验证账户或余额。doctor 提供配置文件位置和启动提示，助手仍按 README 核对实际命令。官方 Serve 工程先用自身的 `npm run configure` 初始化缺失的本机登录材料，保留已有设置，再分别启动 Serve 和登录服务；这是项目自己的配置命令，与 Skill 的 `configure-project` 不同。再核对自己启动的本项目 PID、命令行及工作目录，正常停止并等待收尾后按该项目实际命令重启。不按进程名结束所有 Node/Serve，不碰其他工程。分别核对客户端和所需后端已启动、地址接线、健康及错误，并从界面完成一次端到端流程；真实分析仅在已有费用授权范围内进行。失败不静默切回 offline，也不自动重放结果未知的收费请求。
- **必要的回显例外。** 默认不索取聊天中的密钥，也不在 doctor、常规日志、截图或交付报告回显。若确实有助于本次排查，可在当前受控界面以最小必要范围展示；提醒用户排查完成后适时轮换，并同步更新相关后端配置。此例外不允许密钥进入公开日志、客户端或仓库，也不自动授权轮换；轮换前说明旧键立即失效的范围。

用户未准备平台应用时，助手继续完成包含所需后端的本地运行链路、明确标记的 offline 流程和可点击配置入口，解释“现在是离线规则演示；填好平台应用后由我协助接通真实 AI”。实际换票和平台调用保留未验状态，不能只让用户自行寻找文件、建立后端、取消注释、切换模式和猜测重启方式。

交接时写清“用户下一步在哪个入口配置什么”“助手已经协助完成什么”“应看到什么结果”。不为配置方便读取或覆盖整个用户配置。注册、开通能力、轮换密钥、充值和部署沿已有授权执行；没有授权的外部动作先完成可审阅准备，再说明具体影响。

成功状态分开记录：本地流程通过、真实平台调用通过、可发布构建通过、实际部署完成。某一步未运行时保留该状态，不把模板既有验收代写为用户工程已经成功。

## CLI 起步和日常使用

确认 Node ≥ 22.19、操作系统与现有 CLI 版本；已安装就复用，不无故升级。本次已核实版本的新安装命令为 `npm install -g @tansr/cli@0.10.2`；这是 CLI 安装，不是 Skill 安装。不适合安装 Node 时先核实官方 SEA 包、目标系统和 SHA256SUMS，不编造下载地址。CLI 命令叫 `tansr`，包叫 `@tansr/cli`。

1. 在本机运行 `tansr init`，用户自己完成向导要求的登录。使用 PAT 路径时，在实际控制台创建 PAT，再在本机掩码交互输入。不要把 PAT 发到聊天或放入 `--pat` 命令历史。CI 使用秘密环境变量 `TANSR_PAT`。
2. 平台模式下模型和价目由平台下发；不需要手写 provider。运行 `tansr doctor` 查看装配状态，再用 `tansr` 进入 TUI。
3. 常用 `/status`、`/model`、`/cost`、`/usage`、`/doctor`、`/help`。自动化用 `tansr -p "任务" --json`，持续消费 NDJSON，末尾 result 与退出码决定结果。

`init` 不调用模型，但会验证身份并创建/轮换设备凭据，执行前应已有相应登录授权；用户负责秘密输入。`logout` 清本机凭据并尽力停用设备键，不吊销原 PAT，也不删除会话数据。

headless 没有询问界面，ask 默认拒绝。只为已授权工具给精确规则，不默认加 `auto`、`bypassPermissions` 或信任全部仓库。ACP 是编辑器协议；MCP serve 是另一个入口，涉及它们再查当前命令参考，不能照旧首页“四种形态”漏掉新入口。

退出码基线：0 成功、1 模型/内部错误、2 中止、3 预算或轮数触顶、4 输入过长、5 用法/初始化错误。具体 result.reason 与错误码一起判断。

## 配置来源与本地供应商

settings.json 为 JSONC，优先级由高到低是 managed → projectLocal → projectShared → user → builtin。`permissions` / `hooks` / `mcpServers` 有专门合并与信任规则，不能简单当普通深合并。

先检查 `doctor` 的 config_sources、config_diagnostics、model_resolution 和 localProviders，再决定改哪层。项目层不能自己扩权；用户/组织治理上限不能通过项目配置绕过。不要覆写整个用户配置以修一个项目。

完全本地供应商模式用 `TANSR_ESCAPE_LOCAL=1` 并配置 provider/别名，密钥只通过环境变量名 `auth.env` 引用。这会停止平台模型/配置/用量链，应解释变化而不是偷偷用它规避接入错误。脚本语法适配当前 shell，不向 PowerShell 用户照抄 Bash 的行内赋值。

沙箱/CI 隔离可用 `TANSR_USER_HOME`，或更精确的配置/存储根变量。仅在需要时设置；环境隔离不等于授权执行不可信项目 hooks/MCP/plugins。

## 账户和凭据容易混淆的地方

通过官网入口进入实际控制台，根据真实界面处理，不凭文档猜当前按钮名称。

- PAT 代表个人，供 CLI 初始化；应用页创建的 appid/appkey 代表应用。
- 创建应用先确认个人/组织归属与平台类型；多端按当前平台规则配置独立 appid。终端用户通常不需要 Tansr 账号。
- 应用模型授权、能力开关、系统角色与本地工具配置是不同层。改系统角色不自动开权限。
- appkey 保留服务端；泄露后轮换会使旧键立即失效，应明确部署更新范围；不未经要求轮换现有键。
- 排查账单用时间、订单/请求标识和已脱敏错误；不是索要全量会话内容或凭据。

平台 SDK 的换票接线见 [SDK 参考](sdk.md)，移动应用见 [Serve](serve-mobile.md)。不要把 CLI 的 PAT 初始化当成平台应用接入，也不要把自有供应商示例的 `MODEL_API_KEY` 当成 appkey。用户选择自有供应商模式时才使用对应参考；真实平台接入失败不能自动切成其他计费来源或模拟回答。

## 解释费用，不预设购买

准备 Skill 或安装运行依赖不代表已经开通模型、取得额度或完成付款。用户询问费用时，在当前控制台、价目或服务端报价中分别核对应用额度、模型/媒体调用与所属个人/组织账户；不要仅凭安装成功要求购买套餐。

免费创建应用不等于免费模型调用。模型目录的计量单位、缓存规则、媒体和搜索价格、BYOK 费用分别核对，不把 token 数直接换算成金额；未取得报价或账单时明确标为未知。

给选择建议前查当前套餐、模型目录与服务端报价，并了解用户预计的应用数、活跃会话和用户规模。并发按当前服务端口径，不等于注册人数。用户没有估算时建议从小范围验证收集实际用量；不要假称已经有成本或转化实测。购买、充值和合同选择留给用户明确决定。
