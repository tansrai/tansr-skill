# 从需求到可以验证的产品

适用于用户只有一句普通想法，或想为已有产品增加能力。先读现有项目、用户提供的资料和已经确认的决定；用户不必预先指定平台或写配置指令。只讨论方案时保持只读；开发请求则结合已知事实和可修改默认项持续推进。

## 需求记录

用项目已有任务文件记录以下内容；没有合适位置时使用 `PRODUCT.md`。保持简短，随着实际决定更新，不要求用户填写整张表。

| 记录 | 需要确定的事实 |
|---|---|
| 使用者与任务 | 谁在什么情况下使用，最后完成什么动作 |
| 输入与数据 | 用户输入、已有接口、文件或设备来源；未知数据不编造 |
| 输出与动作 | 页面、文件、结构化结果或业务写入；哪些动作需确认 |
| 平台与使用范围 | 电脑程序、手机 App、浏览器网站或命令行；目标操作系统、是否需安装包；本机单人还是服务多用户 |
| 已有资源 | 项目技术栈、登录、业务 API、平台应用、可用开发环境 |
| 第一条完整流程 | 可观察的输入 → 业务处理 → AI/工具 → 结果；使用什么证明完成 |
| 后续改进 | 当前不需要实现的功能、已知假设、待补配置与下一步 |

技术水平不明时用业务语言解释选择，例如“电脑程序安装后从桌面打开；手机 App 适合随身记录和设备能力；网站从浏览器打开，也便于分享”。这不是套餐选择。没有明确形态时，只作一次简短咨询或邀请补充，例如“你主要会在哪种设备上使用？没有偏好也可以，我会按用途推荐并开始。”已有答案不重复问。用户没有偏好、让助手决定、暂不提供或未补充时，说明推荐默认项及理由、记录为可修改假设，接着开始已授权的本地开发，不结束在等回答。根据实际使用习惯、设备能力、分享范围和现有环境选择；需要随身记录、桌面交互或浏览器分享的场景可以有不同结果，不能因为 Web 模板现成就一律做简陋网页。电脑程序不只适用于本地文件任务；手机 App 不等于手机尺寸的网页。

用户明确选手机时，保留手机目标，优先从已有信息确定 Android、iOS 或原生鸿蒙；电脑按 Windows、macOS 或 Ubuntu 等目标核查构建条件。操作系统仍未知时，说明基于可用环境的暂定选择并先做可逆的工程准备与公共业务，不反复追问或改掉手机/电脑目标。参考[平台与公开产物](platforms.md)选择正式发行依赖。缺少设备或构建环境时可以先完成公共业务与后端，明确原生构建/安装待验，不将网页、源码或后端当作已交付 App。不因现有项目不是模板技术栈就重建项目。推荐默认项只用于已授权实现，不把用户未回答当成付费调用、发布、账户变更或凭据轮换的授权；需要这些动作时沿用原有授权边界。

## 把产品功能与 Agent 工作分开

界面、数据校验、身份授权、统计计算和可靠写入由普通业务代码完成。Agent 用于理解任务、选择工具和生成需要推理的结果。先列出用户实际操作，再选 Agent 能力，避免所有需求都变成一个聊天框。

工具连接真实业务函数，绑定宿主已验证的身份。模型返回“已保存”不代表写入成功；确认工具回执或数据库状态后再呈现结果。根据任务需要接流式进度、取消、会话与恢复，不为一次本机任务预建集群或多租户系统。

## 健身助手示例

用户提出：“我想做一个智能健身助手，每天根据我的情况提供健康及健身建议，分析我的身体状况，提出更长久的健身意见。”

若前文没有说明，可以简短邀请“告诉我你常用的设备和想记录的内容；没有偏好，我会按日常使用场景推荐并开始。”日常随身记录可推荐手机；用户未补充时，说明选择的可修改平台假设和首条流程，继续本地实现。选择 Android、iOS、原生鸿蒙或其他适合的形态应有场景与环境依据，不能把未知设备一律解释成 Android 或网页。不要默认接入穿戴设备、读取医疗记录或要求填写所有健康信息。可选择的首条流程为：填写自愿提供的目标和今天的情况 → 保存日记录 → 生成供用户参考的运动安排 → 查看历史记录与变化依据。

实现可能包含记录表单、历史列表、建议展示和修改/删除。长期分析必须来自实际保存的记录；记录不足就说明不足。开发阶段采用明确标注的合成数据，不伪造真实身体指标；产品区分一般生活/运动建议与医疗诊断，需要专业判断的问题给合适求助入口，不生成未经依据的诊疗结论。

这只是设计示例。原型不自动接入定时推送、支付、穿戴设备或公共发布；根据用户要求继续补齐。

## 不同领域与已有项目

资料助手需要资料来源、检索依据和可追溯结果；订单助手需要授权订单 API 与用户资源隔离。不能只更换反馈工作台标题，保留与需求无关的数据和工具。

已有项目先定位页面入口、身份和业务 API，复用已有实现；不替换项目登录、框架和数据库。先记录原行为，再接入一条 AI 流程并检查兼容。用户已改的文件先读取与合并，不用整目录模板覆盖。

完成当前需求后留下可启动入口与验证结果。用户继续说“再加每周回顾”时，读取同一需求记录和项目代码，核对历史数据并增量实现，不重新生成另一份互不相连的工程。
