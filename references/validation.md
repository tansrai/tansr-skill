# 验证与继续交付

验证针对用户要求的真实行为，不以文档、截图或测试名称替代结果。沿项目已有检查；只有受影响的必要验证才新增测试，冻结候选后集中执行完整门。

## 按交付范围检查

| 交付内容 | 观察方法 |
|---|---|
| 新产品界面 | 实际启动，操作输入、提交、加载、空状态、失败、取消和结果；核查窄屏与键盘行为 |
| 业务动作 | 输入真实或明确标记的示例记录，核对工具回执、数据变更和结果引用；固定计算由代码核算 |
| 实际 Agent 执行 | 工具真实执行且结果进入下一次 SDK 模型请求；标明 provider 是脚本还是实际模型 |
| 已有项目 | 改动前后核心流程兼容；用户修改、框架、登录、依赖和数据保留 |
| 会话或历史 | 记录写入确认后重启，恢复同一份历史；损坏报明确错误，不用新空目录掩盖丢失 |
| 多用户 | 只有项目确实提供身份系统时，检查 A/B 不能互读、改写、恢复对方数据和会话 |
| 平台与付费媒体 | 确认账号授权、模型能力和请求范围，未知结果不自动重发收费任务；端侧不持长期密钥 |
| 原生应用 | 使用该平台实际构建/安装流程，操作关键界面与网络路径；静态代码或模拟 HTTP 不能代替设备实证 |
| 部署 | 环境、身份、存储、启动、停止与健康检查齐全；明确实际部署目标及有效授权 |

脚本模型驱动真实 SDK 能证明接线和错误语义，不能证明真实模型质量、平台计费、账户可用或原生设备体验。缺少凭据时完成本地可执行部分和配置入口，真实模式不得自动回落离线答案。

## 交接的最小内容

交付时给出成果路径、一个准确启动命令、可打开的地址/安装物、已完成的用户流程、验证结果和具体剩余项。分别陈述代码生成、本地可运行、真实平台调用、发布构建、正式上线。配置只列变量名和安全设置位置，不回显密钥。

核对交付形态与用户明确选择或已说明的默认假设一致；用户后续明确选择时及时更新需求记录，不把助手假设写成用户确认：电脑程序给实际可打开的桌面入口及构建/安装状态；手机 App 给对应平台工程、安装物和设备实测范围；网站给准确网址及本地/公网状态。源码、浏览器预览和后端就绪分别说明，不能互相代签。

需要平台配置时，说明是否已有应用、用户在哪里安全录入、助手已经完成的模式检查与重启、还缺的实际验证。用户不懂 `.env` 时按[产品使用](use.md)协助完成，不用“自行配置环境变量”结束交付。

完成已授权需求后，给 2—3 个与当前产品有关的继续方向，避免泛泛列全部技术路线。例如健身助手可以继续做“手机随身记录”“电脑查看长期趋势”或“网站与教练分享”；分别说明能复用什么、还需要开发/验证什么。明确哪一版已经可用，其他形态是下一步选择，不承诺一键转换。用户已经要求做手机 App，就先完成该项，不能以“后续可做手机”替代。用户继续选择后沿原需求与代码增量实现，不再要求确认已有授权的普通实现工作。

已有任务文件继续记录：当前需求、已确认决定、依赖版本、数据位置、启动命令、验证记录、下一步。不要新造一套复杂状态平台或重复维护多份清单。

## 中断与失败

先复现触发条件并查看安全错误码、依赖版本和近期改动。已有确定的失败输入先修复再运行受影响检查，不循环重建整个项目。

缺少平台偏好时按[需求与产品说明](product-brief.md)说明默认项并推进，不把普通平台咨询列为等待条件。需要等待模型、浏览器、设备、凭据或部署条件时，保留已完成代码与最小复现入口，继续独立可完成工作。不能勾选缺失的实测项，也不因为一个原生平台缺少环境就放弃已完成的网页与后端。

结果未知的业务写入先查询状态再决定是否继续。收尾失败保留宿主资源和原始失败原因，通过受控日志诊断；只向界面返回适当摘要。新增身份/存储/部署能力时重新检查相应边界，不把本机单用户样例当公网多用户系统。
