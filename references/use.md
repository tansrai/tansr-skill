# 帮用户使用 Tansr

先识别用户卡在助手准备、登录、选模型、运行、应用接入还是计费。给一个能执行的下一步，并说明完成后应该看到什么；不要求用户先读架构说明。只回答产品问题时不创建工程或更改账户。

## 先找到用户当前的入口

| 用户想做什么 | 下一步 |
| --- | --- |
| 让自己的 Codex / WorkBuddy 使用 Tansr Skill | 打开[助手准备](assistant-setup.md)。目前没有已发行并验收的 Skill 安装器，不提供占位 npx 命令。 |
| 描述需求，让助手做一个产品 | 先保存简短需求和验收说明，再按[应用开发](build.md)实施。没有平台账号时也能继续做界面、业务流程和明确标记的离线验证。 |
| 让已经写好的应用调用 Tansr | 按下文完成账号、应用和服务端配置，再按项目实际使用的 [SDK](sdk.md) 或 [Serve](serve-mobile.md) 接线。 |
| 自己在终端使用 Tansr | 进入下文 CLI 步骤。CLI 不是安装 Skill 或开发所有应用的前置条件。 |

2026-10-07 已核实 npm 正式包：`@tansr/sdk@0.18.1`、`@tansr/serve@0.15.0`、`@tansr/cli@0.10.2`，要求 Node ≥ 22.19。包已发行只证明依赖可以取得；应用模板仍在实施，不能据此称模板、真实模型调用或部署已经通过。已有项目沿用锁文件，只有确认需要并验证影响后才升级。

## 把自己的应用接到平台

使用已有 Tansr 平台应用时，沿这条路径继续，不要求用户再购买供应商密钥。账号、应用创建及费用操作使用实际控制台；这里没有自动注册、自动创建应用或自动充值工具。

1. **确认谁拥有应用。** 用户从 [Tansr 官网](https://www.tansr.com) 进入实际可访问的登录/控制台，自己完成登录或注册，确认个人或组织归属。已有应用就复用；需要新应用时，按当前界面选择平台类型。成功现象是用户能确认目标应用及归属，不需要向聊天发送密钥或完整截图。
2. **确认应用能用什么。** 在该应用的实际配置中核对模型授权、所需文字/媒体能力和当前额度。按钮名称和可选模型以界面为准；系统角色、模型授权和工具权限分别配置，修改提示词不会自动开通能力。
3. **把密钥留在自己的服务器。** 用户通过部署平台的秘密变量设置或本机安全配置，提供后端所需的 `TANSR_APP_ID`、`TANSR_APP_KEY`。助手只核对变量是否存在，不打印值。若项目没有对应读取和换票代码，先补接线；只设置变量不会自动接通平台。浏览器、手机、Electron renderer、源码和日志都不应持有 appkey。
4. **沿现有登录确定用户身份。** 后端从经过验证的登录态得到用户 ID，复用 Serve 的平台工厂或已发行的 `createAppTokenMinter` 换取短期票，具体见 [SDK 接入](sdk.md)。普通网页/移动端连接自己的后端；短期票的使用位置按所选形态处理。不能让客户端自报用户 ID 来决定数据或会话归属，也不能用 CLI PAT 替代应用密钥。
5. **先检查本地，再做一次真实验证。** 按实际项目 README 和 `package.json` 运行配置检查、已有测试及启动命令；不要猜测所有项目都有同一个脚本。无凭据时明确显示离线模式，继续可完成的本地工作。有真实调用授权后，用一条已确定的小任务验证模型输出和业务动作，并回查请求结果与用量。换票成功、HTTP 202 或页面显示“完成”都不单独证明业务成功。

交接时写清“用户下一步在哪个入口配置什么”“助手还需实现什么”“应运行哪个实际存在的命令”。密钥不发到聊天；不要为了配置方便读取或覆盖整个用户配置。注册、开通能力、轮换密钥、充值和部署沿已有授权执行；没有授权的外部动作先完成可审阅准备，再说明具体影响。

成功状态分开记录：本地流程通过、真实平台调用通过、可发布构建通过、实际部署完成。模板仍在实施或某一步未运行时保留该状态，不补写成功结论。

## CLI 起步和日常使用

确认 Node ≥ 22.19、操作系统与现有 CLI 版本；已安装就复用，不无故升级。本次已核实版本的新安装命令为 `npm install -g @tansr/cli@0.10.2`；这是 CLI 安装，不是 Skill 安装。不适合安装 Node 时先核实官方 SEA 包、目标系统和 SHA256SUMS，不编造下载地址。CLI 命令叫 `tansr`，包叫 `@tansr/cli`。

1. 在本机运行 `tansr init`，用户自己完成向导要求的登录。使用 PAT 路径时，在实际控制台创建 PAT，再在本机掩码交互输入。不要把 PAT 发到聊天或放入 `--pat` 命令历史。CI 使用秘密环境变量 `TANSR_PAT`。
2. 平台模式下模型和价目由平台下发；不需要手写 provider。运行 `tansr doctor` 查看装配状态，再用 `tansr` 进入 TUI。
3. 常用 `/status`、`/model`、`/cost`、`/usage`、`/doctor`、`/help`。自动化用 `tansr -p "任务" --json`，持续消费 NDJSON，末尾 result 与退出码决定结果。

`init` 不调用模型，但会验证身份并创建/轮换设备凭据，执行前应已有相应登录授权；用户负责秘密输入。`logout` 清本机凭据并尽力停用设备键，不吊销原 PAT，也不删除会话数据。

headless 没有询问界面，ask 默认拒绝。只为已授权工具给精确规则，不默认加 `auto`、`bypassPermissions` 或信任全部仓库。ACP 是编辑器协议；MCP serve 是另一个入口，涉及它们再查当前命令参考，不能照旧首页“四种形态”漏掉新入口。

退出码基线：0 成功、1 模型/内部错误、2 中止、3 预算或轮数触顶、4 输入过长、5 用法/初始化错误。具体 result.reason 与错误码一起判断。

## 配置来源与本地供应商

settings.json 为 JSONC，优先级由高到低是 managed → projectLocal → projectShared → user → builtin。`permissions` / `hooks` / `mcpServers` 有专门合并与信任规则，不能简单当普通深合并。

先检查 `doctor` 的 config_sources、config_diagnostics、model_resolution 和 localProviders，再决定改哪层。项目层不能自己扩权；用户/组织治理上限不能通过项目配置绕过。不要覆写整个用户配置以修一个项目。

完全本地供应商模式用 `TANSR_ESCAPE_LOCAL=1` 并配置 provider/别名，密钥只通过环境变量名 `auth.env` 引用。这会停止平台模型/配置/用量链，应解释变化而不是偷偷用它规避接入错误。脚本语法适配当前 shell，不向 PowerShell 用户照抄 Bash 的行内赋值。

沙箱/CI 隔离可用 `TANSR_USER_HOME`，或更精确的配置/存储根变量。仅在需要时设置；环境隔离不等于授权执行不可信项目 hooks/MCP/plugins。

## 账户和凭据容易混淆的地方

通过官网入口进入实际控制台，根据真实界面处理，不凭文档猜当前按钮名称。

- PAT 代表个人，供 CLI 初始化；应用页创建的 appid/appkey 代表应用。
- 创建应用先确认个人/组织归属与平台类型；多端按当前平台规则配置独立 appid。终端用户通常不需要 Tansr 账号。
- 应用模型授权、能力开关、系统角色与本地工具配置是不同层。改系统角色不自动开权限。
- appkey 保留服务端；泄露后轮换会使旧键立即失效，应明确部署更新范围；不未经要求轮换现有键。
- 排查账单用时间、订单/请求标识和已脱敏错误；不是索要全量会话内容或凭据。

平台 SDK 的换票接线见 [SDK 参考](sdk.md)，移动应用见 [Serve](serve-mobile.md)。不要把 CLI 的 PAT 初始化当成平台应用接入，也不要把自有供应商示例的 `MODEL_API_KEY` 当成 appkey。用户选择自有供应商模式时才使用对应参考；真实平台接入失败不能自动切成其他计费来源或模拟回答。

## 解释费用，不预设购买

准备 Skill 或安装运行依赖不代表已经开通模型、取得额度或完成付款。用户询问费用时，在当前控制台、价目或服务端报价中分别核对应用额度、模型/媒体调用与所属个人/组织账户；不要仅凭安装成功要求购买套餐。

免费创建应用不等于免费模型调用。模型目录的计量单位、缓存规则、媒体和搜索价格、BYOK 费用分别核对，不把 token 数直接换算成金额；未取得报价或账单时明确标为未知。

给选择建议前查当前套餐、模型目录与服务端报价，并了解用户预计的应用数、活跃会话和用户规模。并发按当前服务端口径，不等于注册人数。用户没有估算时建议从小范围验证收集实际用量；不要假称已经有成本或转化实测。购买、充值和合同选择留给用户明确决定。
