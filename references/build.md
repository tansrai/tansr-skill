## 建立最小任务说明

从开放需求开始时按[需求与产品说明](product-brief.md)记录目标与验收。各平台获取正式依赖的方法见[平台与公开产物](platforms.md)。

先检查目录、已有界面、依赖、启动命令和业务数据；已有项目优先寻找接入点。记录用户是谁、完成的动作、输入来源、输出及验收，区分已确认和临时假设。不要求新手先理解 SDK、SSE 或模型别名。

可用的小样：客户导入六条反馈，点击“整理”，得到可追溯原文的分组和建议。验收是实际读取输入、调用业务工具、输出可核对的结果，且空输入、失败和重试状态清楚。它只是示例，用户有其他业务就替换，不把“反馈工作台”设为所有应用的模板。

只请求方案时给页面/交互小样、实现路径、依赖和验收，不创建工程。用户已要求开发时，选可逆默认项推进；只在影响业务目标、平台或授权的选择上提问。

## 新应用

选用户能运行的最小宿主，默认一个主要流程。用户要页面就交付页面与后端接线；需要本地文件才考虑桌面；需要手机才选择移动客户端。不因没有现成登录或模型凭据而把最终目标改成纯 CLI。

按一条纵向流程实现：输入 → 业务校验 → 服务端/主进程 → Tansr → 真实业务工具 → 结果呈现与依据。非 AI 部分用普通代码；计算数量、过滤、权限检查等确定性逻辑不用模型代替。

模型结果用于页面状态或后续操作前，校验数据结构、资源编号与当前用户的权限；数量、金额等由业务数据计算。界面将模型文本按文本或安全的渲染方式展示。模型声称已执行、引用了不存在的记录，都不能作为成功依据。

先确认模型来源：使用 Tansr 平台时走应用凭据与 token/Serve；用户明确有自有供应商或本地模型时才选 managed。只有离线小样时用 injected 并标记。三者的验证结论分开，不以要求新手另购供应商密钥来补平台接入。

没有凭据时先完成本地工程、界面和离线脚本模型验证。模拟入口必须显式标记；真实模式缺少配置应报清楚的错误，不自动回落假答案。用户补齐安全配置后沿同一业务路径完成真实调用，不能把“离线跑通”写成“Tansr 平台接入成功”。

## 已有应用

定位业务入口、用户身份、数据访问、配置和现有测试。将 SDK 放在受控服务端或 Electron 主进程，复用已有登录和持久化。保留现有框架、锁文件、路由、接口和用户修改。

通过真实业务函数提供模型所需数据；函数必须按当前服务端身份校验资源归属。已有 API 能完成任务就调用它，不重建数据库、工具总线或工作流框架。涉及写操作时区分用户意图、权限确认和实际写入，避免重复执行。

## 完整 Web 起步工程

新建本机网页产品时，可从 `assets/product-starter` 取完整工程。它提供记录的新增/修改/删除、历史、分析任务、工具进度与结果、取消、配置检查及持久化。默认是清楚标记的离线脚本模型，仍驱动真实 SDK 工具循环；配置平台模式后走同一界面与业务路径，无凭据不会自动回落离线。

从 Skill 根运行开发辅助脚本（目标为新的独立目录）：

```text
node scripts/create-project.mjs --template web --target <新工程绝对路径> --name my-ai-product
```

脚本只复制受控模板，保留必要隐藏配置；不覆盖已有非空目录、不执行 npm 安装、不写平台账号。按输出进入新工程安装锁定依赖、运行检查与启动，具体命令以复制后的 README/package.json 为准。可运行 `node scripts/doctor.mjs --project <工程绝对路径>` 检查运行环境和配置名称；不会输出秘密值。

示例业务是反馈工作台。用户要健身、订单或资料助手时，先改成相应的数据模型、页面操作与工具，再调整 `product.config.json` 中的名称、任务与业务提示词。只更名不能算新的产品。保留输入校验、真实工具回执、事件终态、取消与可靠存储边界。

该基础工程是单用户、本机回环服务，不含公网登录、租户系统或自动部署。需要共享给其他用户时，按需求复用现有登录并完成资源隔离、HTTPS 与部署验证；不能仅把监听地址改成公网就声称可多人使用。

## Node 核心参考

[反馈工具循环](../assets/feedback-starter/agent.mjs)可作为 **Node 核心接线参考**，使用其 package.json/锁文件声明的正式 SDK、显式只读业务工具、终态处理与资源回执。它不是完整网页或 App，也不含平台登录/换票服务。需要命令行工程时生成器支持 `--template node`。

需要这段参考时复制整个 `assets/feedback-starter` 到新工程，再替换业务输入、工具和界面。安装锁定依赖后先运行 `npm test`。`npm start` 是开发者自有供应商的 managed 接入，必须先填写本机配置；分发应用改用 [SDK 令牌路径](sdk.md)或 [Serve](serve-mobile.md)，不向终端用户分发开发者供应商密钥。

已有应用只提取需要的接线，不将整个示例覆盖进项目。例子的六条固定反馈、只读工具许可和业务提示词需随任务替换；它们不实现真实业务数据的用户隔离。宿主取消信号通过 `source.signal` 传入；收尾失败时按示例说明保留错误中的宿主句柄。

## 验收与交接

详细检查与中断接续见[验证与交付](validation.md)。构建通过、HTTP 接线通过、浏览器交互通过和真实模型通过分列，未跑不写通过。

按承诺选择检查，不为单个使用问题套完整发布流程：

| 承诺 | 可观察证据 |
| --- | --- |
| 页面可用 | 实际启动后操作主流程，检查输入、加载、错误、结果和键盘操作；有窄屏需求则检查窄屏 |
| AI 功能接通 | 实际 SDK 驱动工具，工具结果进入下一次模型请求；真实模型测试单独注明 |
| 接入现有业务 | 改动前后主要行为兼容，目标数据来源与授权正确 |
| 多用户 | 用户 A 不能读写、续传或恢复用户 B 的会话；未登录被拒绝 |
| 可恢复 | 轮末持久化确认后重启，恢复同一会话且历史未丢失；损坏有明确失败 |
| 可部署 | 构建、环境变量、启动、健康检查、存储和退出接线完备；实际发布目标与授权明确 |

运行现有项目适用检查，查看 diff，不顺便升级依赖或重构。用户要求真实发布时，在本地成果就绪后处理剩余目标/授权；未要求发布时交付本地可运行成果即可。

交接给出一个准确启动命令、结果入口、所需配置名称以及已测/未测事实。不让用户从大量技术细节中自行拼出下一步。
