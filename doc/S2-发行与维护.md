# 第二阶段发行与维护

归属 TPB-01 原 S2-06—08；实际发行结果写入 S2 回执。开发仓是 private workspace，只有 `dist/npm` 是公开 npm 包。不要在仓库根直接发布，也不要把源码目录直接上传为 Skill。

源码公开仓为 `https://github.com/tansrai/tansr-skill`；上述private仅指根package.json禁止误发npm，不表示GitHub仓为私有。Tansr自有代码MIT，继承的Apache来源与Demo原许可保留；根与Skill内的LICENSE、NOTICE和LICENSES必须一起分发。

## 维护入口

`release.json` 定义包名、版本、bin、Node 要求和发行标签；`compatibility.json` 记录 Skill、模板与运行依赖基线。修改任一模板、准备脚本或宿主适配时，重新核对应字段及受影响的消费链。公开说明来自 `INSTALL.md`；构建时复制为 npm README。

`scripts/build-installer.mjs` 按固定白名单取得已版本化文件，生成内容清单；两份模板的 `.gitignore` 在包中编码为 `tansr.gitignore`，安装器依据清单恢复原名，避免 npm 解包把它转换或过滤。逻辑路径与来源路径都须通过验证；不能靠忽略所有点文件解决打包问题。新增公开资产要先经过审查，再加入白名单。

## 冻结与本地门

开发结束后记录 Git 起点、候选文件清单和摘要，集中执行：

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm typecheck
pnpm lint
pnpm build
pnpm check:package
```

`check:package` 检查真实 tarball、重复打包指纹和 npm 实际解包结果。其通过不代表宿主已发现 Skill；仍须按原 A2 在隔离目标验证公开 CLI 的安装、状态、更新/回退、恢复、卸载，以及 Codex/WorkBuddy 实际读取。不要用模拟宿主回执代签真实加载。

测试仅使用合成项目与任务专属临时目录，保留用户项目、其他 Skill 和真实凭据。源码完整门、包门、宿主行为、公开 registry 及产品运行是分别可核查的证据层。

## 主线与候选发行

1. 原本地门通过后收编 main，推送 main；开发分支不推送。
2. 按需执行 `.github/workflows/ci.yml`，核对 run 的 `headSha` 与待发布 main 精确一致，Windows、Linux、macOS 安装器门分别记录。此 CI 不保存 npm token，不发布包，不声称桌面宿主 UI 已验。
3. 从同一主线字节重新确认 tarball SHA256、npm integrity、版本与包名。用已有本地发布身份执行 **精确 tarball** 的 `npm publish --access public --tag next --ignore-scripts`；不要使用默认 latest。
4. 回读 registry 的精确版本、候选标签、tarball 与 integrity，保存原始响应和实际下载摘要。2FA 或发布权限不足时，保留待发布产物，不尝试换身份绕过。

正式发布所需的授权依当前会话与原方案判断；既往其它批次的 CI 例外不能套用。候选公开后，npm 的版本不可原位覆盖；发现缺陷应修订版本，并重新完成受影响验证。

## 公开闭环与正式入口

使用独立缓存、无仓库源码依赖的临时项目，从公开 registry 取得候选精确版本，执行 npx 安装。核对实际安装文件摘要与候选清单；验证目标助手从这一路径读取，提交一个新需求并运行生成产品。实际读取或产品运行失败时，不移动 `latest`。

原 A2 完成后，记录旧标签，执行 `npm dist-tag add @tansr/skill@<已验精确版本> latest`。随后用最终 `@latest` 命令再次确认解析为同一已验版本及完整性。首次发行没有旧 latest 时，未完成不得宣传正式入口可用。

首页在第三阶段消费正式发行事实；本阶段不修改主页，也不凭安装命令执行成功统计产品完成。

## 用户更新与异常恢复

发布新版本先走 next 验证，保留此前已验版本。用户的 `update` 仅更新可证明未被修改的受管文件；回退使用原安装记录保留的前版。未知或用户修改文件保留，冲突返回非零并列出下一步。不要建议用户删除整个 `.agents` / `.codebuddy` 目录重新安装。

中断先执行 `status` 查看；确认原进程结束且状态提示需要恢复时，执行同一目标的 `recover --yes`。恢复仍检测冲突；状态或归属资料不可信时停止处理并保留资料供诊断。不要靠调整锁超时或删除锁文件强行启动第二个安装进程。

缺 Node 时按官方渠道安装满足版本的 Node/npm；网络失败先保留错误和现有安装，核对公开 registry 可达后由用户重新执行；权限不足应选择有写权限的用户/项目范围，不默认管理员提权。缺少这些条件不能返回“安装成功”。
