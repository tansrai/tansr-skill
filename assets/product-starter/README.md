# 本机产品基础工程

这是可修改的完整 Web 纵向流程：浏览器录入真实记录 → 受控 Node 后端 → 正式 Tansr SDK 调用业务工具 → 流式进度 → 保存结果和输入快照 → 历史回看。初始业务为反馈工作台；它是单用户本机工程，不提供远程登录或多用户隔离。

## 安装与启动

需要 Node.js **22.19 或更高版本**及其自带 npm。运行本工程目录下的命令：

```sh
npm ci --ignore-scripts
npm run dev
```

打开终端显示的 `http://127.0.0.1:4317`。必须用 `127.0.0.1`，不是 `localhost`。未设置环境时明确使用 **offline** 模式：正式 SDK 驱动规则脚本提供的模型流，真实调用业务工具，但不访问平台或任何真实模型。没有自动插入示例/合成业务记录；请自行输入，例如标题“页面加载很慢”、正文“提交后加载约十秒”。界面可录入、修改、选择分析、取消、删除和回看历史。

可发布构建的本机验证：

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm start
```

`build` 生成 `dist/src` 和 `dist/public`；`start` 使用构建后的前后端。这些命令没有发布、部署或付费调用步骤。npm 锁定直接依赖与传递依赖；运行代码只导入公开 `@tansr/sdk@0.18.1` 与 `@tansr/serve@0.15.0`，不依赖 Tansr 私有仓路径，也不执行依赖安装脚本。首次安装需能访问公开 npm registry。不要将测试成功描述为真实平台调用通过。

## 平台配置

1. 在自己的 Tansr 控制台选择或创建应用，确认应用所属账户/钱包、模型和工具能力授权、余额或套餐。沿用平台应用即可，不强制购买其他供应商密钥。
2. 将本工程的 `.env.example` 复制为本工程 `.env`，在本机安全编辑器中填写 `TANSR_MODE=platform`、`TANSR_APP_ID`、`TANSR_APP_KEY`，必要时设置已核实的 HTTPS 平台源地址 `TANSR_API_BASE_URL`（默认 `https://api.tansr.com`）。不要把真实密钥发到聊天、提交到 Git 或写入前端代码。
3. 重启服务。界面会显示平台模式及配置是否齐全；“配置齐全”不证明账户、余额或模型调用已经通过。选择少量非敏感记录执行一次已授权分析，再核对结果与平台用量。

服务端使用发行包 `createAppTokenMinter`，固定身份为 `local-owner`，换取短期令牌后创建 SDK 会话。同步 token getter 只读取内存，不把 async 函数当 getter。长期 appkey、短期令牌、系统提示词、原始 SDK 错误均不通过 HTTP 返回。每次短任务单独换票/建会话，换票有独立 15 秒上限；SDK 模型/目录请求保留自身取消信号并受整个任务 120 秒上限约束，不受换票计时器截断；不实现长期会话续票。

平台模式在首次 HTTP 拒绝、网络异常、公开 TWP `t.err`、响应流中断或缺失终态时立即封住后续请求，并取消本次 SDK 会话；`202 in_progress` 也停止并交由用户核对，不自动重发。401/令牌过期、403/模型未授权、402/余额不足分别给出安全指引。SDK 自带的重试仍属于核心能力，本模板通过公开 fetch/取消接口在这些失败边界停止本次任务，没有复制 SDK 重试、令牌刷新或协议执行逻辑；协议内容正确性仍由 SDK 检查。会话资源收尾必须得到成功回执，失败回执保留恢复句柄并停止接收新分析。失败不回落离线答案；用户确认状态后才手动新建分析。

维护边界（P07）：上述兼容观察锁定发行 SDK 0.18.1。其公开 `CreateSessionOptions` 没有重试开关或平台错误回调，首次网络失败的 `turn.error` 也会被内部重试推迟；只监听公共事件不足以保证首败停止。观察器只读取有界响应的标准 SSE 行、错误码和终态，JSON 回放只检查文档是否可读，不解释工具、文本增量、权限、用量或完整结果协议。长期应在 SDK 提供公开错误回调/停止策略后替换这层兼容观察。宿主同时等待自己添加的流管道和 SDK 的资源收尾；异步取消失败或超时不算成功，不能通过忽略失败回执恢复接单。

应用身份不是登录功能。网页上的输入不能切换所有者；同一 OS 上其他进程/用户可能访问 loopback。若要服务多用户或对外部署，先使用现有登录系统在后端确定用户身份，为工具、存储和恢复做用户隔离，并接 HTTPS、CSRF/限流、密钥管理、备份与部署方案。本工程不会仅修改监听地址就宣称可公网部署。

## 数据与后续修改

- 数据默认在本工程 `.data/state.json`；`DATA_DIR` 可指定独立目录，`PORT` 可更改端口。`.env` 由启动命令只从当前工程读取，不扫描其他项目或用户目录。
- 保存使用串行事务、临时文件、文件同步和原子替换。保存失败不更新内存中的已确认数据，分析保存失败冻结后续分析，避免误报成功。它不是跨机器数据库或备份系统。
- 每次分析保存 `inputRecords` 快照和最终结果。修改原记录不会重写旧依据；删除原记录会一并删除引用它的历史分析和快照。正在使用的记录必须先结束/取消分析才能删除。
- 单次选择 1–50 条，单条标题最多 160 字符、正文 6000、来源 200；请求体 32 KiB；最多 1000 条记录及 1000 次历史分析。本地工具适用规模内使用，更多数据需迁移存储并重新验证。
- 调整名称、领域、说明和模型业务提示词：编辑 `product.config.json`。扩展业务字段与工具：编辑 `src/types.ts`、`src/store.ts`、`src/product.ts`、`src/agent.ts` 和界面。离线规则整理也要一起调整，不能将反馈分类冒充新领域的真实 AI 建议。
- 内置可扩展的记录状态 `new/reviewed/resolved` 已支持后续进展跟踪，新增逻辑应保留现有记录 ID、时间与分析快照。已有产品接入时复用它的登录/数据/依赖，不覆盖其项目结构。
- SDK 工具只有精确允许的 `readRecords`，只读当前选中记录的快照，没有文件、Shell、任意 URL、浏览器或修改业务数据权限。原记录中的外部指令仅是待分析数据。

HTTP 字段、错误、SSE 恢复与取消合同见 [src/http-contract.md](src/http-contract.md)。浏览器草稿流是临时显示，最终结果以已提交历史为准；断线重连不能自动重发创建分析请求。

## 排错与恢复

| 状态 | 下一步 |
|---|---|
| 平台凭据缺失 | 编辑本工程 `.env` 的服务端配置后重启；期间仍可保存记录。要离线验证须主动选择 offline 并重启。 |
| 令牌过期/凭据拒绝 | 核对应用状态和服务端密钥，重新开始一次分析；不重复提交结果未知的请求。 |
| 模型权限或账户额度不足 | 在应用所属账户核对模型能力授权、余额和套餐，再由用户发起重试。 |
| 网络或平台失败 | 检查目标网关与网络；错误不会被包装成离线成功。 |
| `missing_evidence` | 模型没有实际读取工具或没有可提交的最终文本；选择支持工具调用的已授权模型。 |
| `busy` / `cancelling` | 等待当前会话停止。只有收到 `cancelled` 才表示资源收尾完成。 |
| `store_locked` | 先确认没有任何服务使用该数据目录。正常退出会移除 `.owner.lock`；异常退出后先备份完整目录，核对锁中的 PID 已结束，再手动移除**这一锁文件**。不删除 `state.json`。 |
| `store_corrupt` | 原文件保持不变。停止所有写入，备份目录并检查 JSON/版本，恢复已核对的备份；不能自动新建空库覆盖。 |
| `interrupted` | 先前任务因服务停止中断，不自动重放模型或业务工具。核对记录与平台用量后手动创建新分析。 |
| `storage_failed` | 保留目录、检查磁盘/权限；运行中的结果可能只在内存中，不能声称已保存。修复后重启并核对历史，不自动重跑计费任务。 |
| `cleanup_incomplete` | 保留服务进程与数据锁，检查资源收尾；宿主持有真实 SDK 会话及回执，可继续 drain。不要并行启动另一实例或假称已停止。 |

正常停止用 Ctrl+C，服务先拒绝新写操作，等待在途请求、取消活动分析、检查 SDK 收尾、关闭事件连接与存储。异常退出恢复后，原运行记录标记为 `interrupted`。

## 验证范围

测试使用系统临时唯一目录、假平台 fetch 与脚本 provider，不读实际 `.env`、不调用真实模型。覆盖完整 HTTP/SDK/工具/SSE/保存链、输入校验、同源与 Host 边界、凭据不泄露、并发幂等保存、单任务限制、取消后续跑、模型错误、缺少工具依据、平台签名请求形状、重启恢复、损坏文件保留、竞争锁和持久化失败回执。真实平台计费调用、公开部署、多用户环境与媒体能力尚未由这些测试证明。
