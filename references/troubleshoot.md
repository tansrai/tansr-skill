# 按证据排错

先用一句话确认“在哪一步没有得到什么结果”，再收集实际版本与最少的脱敏错误。不要先让所有人登录、升级或充值，也不要让用户贴完整环境变量、聊天记录或请求头。

## 先分清助手准备与应用运行

| 用户看到的现象 | 下一动作与判断方式 |
| --- | --- |
| 不知道运行哪个 Skill 安装命令 | 当前没有已发行并验收的安装器，按[助手准备](assistant-setup.md)检查手动准备或官方导入入口。不要尝试猜测的 npx 包名。 |
| Codex 找不到 Tansr Skill | 确认所打开项目内有 `.agents/skills/tansr/SKILL.md`，且没有多套一层目录；检查该文件的 name/description 和引用资源。官方会自动检测变化，仍不出现时可由用户重启并重试。不要覆盖已有同名目录或全局配置。 |
| Codex 有同名技能，不知读了哪份 | 对照选择器和助手实际读取的文件路径，先确认目标版本；同名项不保证合并。保留用户原文件，再处理自己管理的副本。 |
| WorkBuddy 导入失败或看不到技能 | 使用实际技能面板的本地导入入口，记录宿主版本和界面给出的格式要求。目录、完整包格式及外部文件重载尚未核实，不能通过写入猜测目录、改名为 skill.yml 或重装助手假装修复。 |
| 文件已复制，助手却没用它 | 分别核实文件存在、宿主可发现、实际读取并使用三个状态。用一个相关任务显式选择技能；还未调用就写“待验证”。 |
| 应用能打开，但回答来自示例数据 | 查看页面模式与后端实际来源；离线结果只证明演示流程。按[产品使用](use.md)配置自己的平台应用，完成获准的真实验证；不隐藏离线标记。 |
| 刚安装 SDK，示例就报接口不存在 | 检查项目实际安装版本、锁文件与发布包 exports/types。本次发行基线为 SDK 0.18.1、Serve 0.15.0；先确定示例是否匹配，不直接升级或删除锁文件。 |
| README 中的模板命令还不存在 | 先检查实际 `package.json` 与模板实施状态，补齐代码和启动说明后再运行；模板尚未验收不能记录成用户环境故障。 |

## 按实际运行证据定位

CLI 从 `tansr doctor --json` 开始；SDK 从装配异常或运行事件开始；Serve 用 HTTP 状态、code、detail.scope 与 x-request-id；移动端看连接状态。输出诊断前先检查其中是否包含用户目录、业务数据或其他隐私。

`doctor` 默认是本地装配诊断，不证明远端可用；`--connectors` 才涉及特定网络探测。其他形态不必为排错安装 CLI。

| 现象或证据 | 应对 |
| --- | --- |
| `invalid_options` | 检查三种模型来源混用、旧 API、工具名称和裁决选项；不循环重试 |
| `assembly_failed` | 核对版本、模型别名、必需环境变量是否存在与平台配置；只查看需要的脱敏 cause，不输出原凭据 |
| `capability_disabled` / `model_not_authorized` / 403 | 查应用能力、模型授权和资源归属；403 不是刷新 token 的理由 |
| 工具全部被拒 | 检查规则、能力门和 askUser/移动审批桥；只读声明不能代替许可，不全局放权 |
| 有文本但任务未执行 | 查实际工具事件、调用次数与业务结果；模型说“完成”不是写入证据 |
| 收到 turn.completed 但结果不完整 | 查 reason，轮数/工具轮数/停止钩子触顶也可使用该事件；不能只按事件名判成功 |
| 事件流一直不退出 | 区分跨轮订阅和单轮终态，检查消费者接线及 closeAsync 回执；不能用固定延时假装完成 |
| `turn.error` 且 recoverable=true | 保留告警，按 scope 处理；存储失败应提示未可靠保存，不当成成功落盘，也不一律中断会话 |
| 401 / `unauthorized` / `token_expired` | 先确认报错来自平台还是自己的后端：CLI 按 init 向导处理；应用端修自家登录/换票，平台层核对服务器配置的有效状态、应用与签名。按[配置陪同流程](use.md#本机配置与凭据处理)处理注释、空值、占位及重复赋值；日常不要求粘贴密钥，必要回显与轮换提醒沿同一边界。有限重试仍失败则停止，不重放结果未知的任务 |
| `signature_invalid` | 查 app-token 换发的签名协议、时间/nonce/请求字节；不要关签名或误当余额问题 |
| 402 / `insufficient_balance` | 请用户在实际控制台核对应用所属的个人/组织钱包及账单；尚未看到该账户状态就不要断言欠费金额。重试无益，不能自动充值 |
| 429 + `detail.scope: 'plan'` / `plan_concurrency_exceeded` | 套餐额度类；展示稍后重试与开发者核对入口，不套自动重试循环、不强推升档 |
| 普通 `rate_limited` / 瞬态 5xx | 尊重 Retry-After 与有限退避，先确认内核已有重试；结果未知的业务写入或收费产物不要直接重放，先查询实际结果 |
| 日/月配额触顶 | 等窗口或由用户调整资源；不是短时间反复请求能解决 |
| Serve 503 | 分清 `overloaded` 本机准入、`upstream_unavailable` 上游、`draining` 停机；别都算网络抖动 |
| `resume_unavailable` | 未接正确 store；连接工厂存储与 v2.store，不假建空会话替代 |
| `session_store_corrupted` / `store_corrupted` | 保留原卷与错误证据，检查多进程共盘/版本混写；有备份再制定修复，不自动删历史 |
| `session_archived` | 平台侧归档，不能将其当普通 SSE 闪断；说明恢复限制，按需新建 |
| 413 / `payload_too_large` | 查实际接口/客户端上限，减少或拆输入；不无限增缓冲/重试 |
| 模拟器/真机连不上 | 检查宿主地址、监听、端口、防火墙、HTTP 开发许可和自有登录，不能关掉鉴权来试 |

尽量先做无模型费用的配置、类型和本地重现。需要真实调用时说明最小验证操作，沿已有授权执行；验证失败不增加未经授权的费用或扩大读写范围。没有凭据时继续可以完成的本地工作，真实平台调用保留待验；不能自动注册账号、创建付费资源或用模拟回答掩盖失败。

修复后重复最小失败步骤，同时检查相关业务结果：能否保存、取消、恢复或继续原任务。报告“改了什么、跑了什么、看到了什么、还有什么未测”。仅进程退出码为 0、包可下载或页面可打开，不能代替模板完整流程、真实平台调用和部署验收。

仍不能定位时，整理运行版本、时间、最小复现、脱敏 code/状态/请求标识以及已排除项。联系支持或上传日志需用户要求；本地诊断不自动外发。即便官方导出宣称脱敏，也检查业务隐私后再共享。
